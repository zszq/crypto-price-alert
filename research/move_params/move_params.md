# 秒级异动：提高提醒质量、减少提醒数量（2026-10-25 ~ 10-26）

用户要求：研究一套秒级异动（`move`）参数，适当减少秒级提醒数量，提高其质量。
代码在本目录，行情、逐秒记录与结果在 `data/backtest/move/`（约 19GB，不进版本库，可整个删除后按第七节重跑）。

第一轮只用了九月一个月选参（第一~七节）；用户认为一个月太少，第二轮把数据扩到 4-02~9-30 半年，用 4~7 月重新选参（第八节）。
之后用户把目标改为「以提高质量为主、顺带减少提醒」，第三轮在同一份数据上按质量分重新选参（第九节）。

**采用情况（2026-10-26）**：对比第二、三轮后，用户选用第二轮推荐，`config/default.yaml` 的 `move.short_window` 曾改为
2.0% / 2.5 ATR / 确认 3 秒（笔数 15、冷却 30 不变）。第三轮的结论保留在下面供参考。
之后用户又把短窗口放宽到 1.3% / 1.5 ATR / 确认 2 秒（笔数、冷却不变），这组取值不是本研究的推荐，下文的数字不适用于它。

## 结论（第三轮，以质量为目标）

建议仍只改短窗口三项，长窗口、冷却和其余参数不动（`sim.ROUND3`）：

| `move.short_window` | 现行 YAML | 建议（第三轮） | 第二轮推荐 |
|---|---|---|---|
| `min_change_percent` | 1.2 | **3.0** | 2.0 |
| `trigger_atr_multiple` | 1.5 | **2.5** | 2.5 |
| `confirmation_seconds` | 2 | **5** | 3 |
| `min_window_trades`、`cooldown_seconds` | 15、30 | 不变 | 不变 |

| | 半年 4-02~9-30（182 天） | 十月 10-03~10-11 |
|---|---|---|
| 质量分（5 分钟保留率 − 假提醒率） | 44.5% → 51.5%（第二轮 51.1%） | 44.3% → 54.6%（第二轮 53.2%） |
| 5 分钟保留率 | 72.3% → 75.7% | 72.7% → 77.4% |
| 假提醒率 | 27.8% → 24.2% | 28.4% → 22.8% |
| 重复率 | 44.3% → 20.2% | 47.4% → 21.8% |
| 每天提醒数 | 1072 → 672（−37%；第二轮 −33%） | 735 → 429（−42%） |
| 其中短窗口 | 438 → 38 | 335 → 29 |
| 大行情 ≥3% / ≥5% 覆盖率 | 88.7% → 87.4% / 92.6% → 91.6% | 92.2% → 91.4% / 95.3% → 94.7% |
| ≥3% 首报中位延迟 | 208 → 223 秒 | 200 → 213 秒 |
| 现行行情段保留率 | 94.2% | 92.2% |

- **质量已接近上限**：在「大行情覆盖基本不降、首报晚不超过 20 秒」的约束下，开发期质量分最高只有 51.4%，第二轮推荐已到 51.0%。
  相对第二轮，建议参数半年只高 0.4 [+0.3, +0.5] 个百分点，十月 1.4 [+0.6, +2.3]；4~9 月逐月都不低于第二轮。
  相对现行则是 +7.0 [+6.7, +7.3]，182 天里没有一天 5 分钟保留率低于现行。
- **限制质量的是首报延迟**：放宽行情段保留没有用，允许大行情首报再晚 20 秒（共约 +40 秒）质量分可到约 55%，
  但现行行情段只剩一半、每天提醒 −62%；完全不管延迟与行情段可到 56%（`quality.py f`）。这属于产品取舍，回测给不出答案。
- **与按规则选中的一组的关系**：第九节规则选出的是同一个短窗口（笔数 60）再把长窗口笔数改为 120，提醒再少约 3 个百分点，
  但质量分略低（51.3%）、现行行情段多丢约 2.5 个百分点（91.7%，接近 90% 下限）。两组都满足全部约束与采用条件，
  只在「同等时取提醒最少」这一步分开；本轮以质量为主，所以建议质量更高、改动更少的这一组（偏离了预先写定的取舍，用户决定）。
- **副作用**：短窗口提醒只剩约 38 条/天，连续提醒几乎消失（半年 5.7 → 0.2 条/天；`streak.min_alerts` 改 2 约 1.8 条/天）。
  丢掉的现行行情段 3316 段（5.8%），93% 只报过 1 条，段内最大涨跌幅中位 1.36%。
- 四月单月 ≥5% 覆盖降 1.4 个百分点，超过 1 个百分点的约束（第二轮推荐同样超过），其余月份都满足。提醒之后的方向仍不可预测（约 47% 对 50%）。

## 第二轮结论（以减少数量为主，已采用）

推荐只改短窗口三项，冷却、长窗口和其余参数不动：

| `move.short_window` | 现行 YAML | 推荐（第二轮） | 第一轮推荐（已被取代） |
|---|---|---|---|
| `min_change_percent` | 1.2 | **2.0** | 2.0 |
| `trigger_atr_multiple` | 1.5 | **2.5** | 2.0 |
| `confirmation_seconds` | 2 | **3** | 3 |
| `cooldown_seconds` | 30 | 30（不变） | 60 |

半年与十月的结果（重放，全天 24 小时口径；`half.py c`）：

| | 半年 4-02~9-30（182 天） | 其中开发期 4-02~7-31 | 其中留出期 8-01~9-30 | 十月 10-03~10-11 |
|---|---|---|---|---|
| 每天提醒数 | 1072 → 715（−33%） | 1076 → 720（−33%） | 1065 → 705（−34%） | 735 → 464（−37%） |
| 其中短窗口 | 438 → 81 | 436 → 80 | 443 → 83 | 335 → 64 |
| 重复率（同合约同方向 5 分钟内已报过） | 44.3% → 24.8% | 44.1% → 24.6% | 44.7% → 25.2% | 47.4% → 27.2% |
| 5 分钟保留率（5 分钟后仍保留一半以上位移） | 72.4% → 75.4% | 72.4% → 75.4% | 72.2% → 75.3% | 72.8% → 76.5% |
| 假提醒率（15 分钟内先回到基准价） | 27.8% → 24.2% | 27.9% → 24.3% | 27.6% → 24.0% | 28.4% → 23.0% |
| 现行行情段保留率 | 94.2% | 94.4% | 93.8% | 92.3% |
| 大行情 ≥3% 覆盖率 | 88.7% → 87.4% | 88.4% → 87.2% | 89.3% → 88.0% | 92.2% → 91.5% |
| 大行情 ≥5% 覆盖率 | 92.6% → 91.7% | 91.8% → 90.9% | 94.3% → 93.5% | 95.3% → 94.7% |
| ≥3% 首报中位延迟 | 208 → 222 秒 | 208 → 222 秒 | 206 → 222 秒 | 200 → 212 秒 |

- **少的主要是重复提醒和小幅波动**：半年里丢掉的现行行情段 3297 段（5.8%），93% 在现行参数下只报过 1 条，段内最大涨跌幅中位 1.36%
  （保留的段为 2.07%）。
- **质量提高的含义**：插针、来回抽的提醒变少。半年按天块自助法：5 分钟保留率 +3.0 [+2.9, +3.2] 个百分点、假提醒率 −3.6 [−3.8, −3.4]，
  182 天里没有一天的 5 分钟保留率低于现行；十月 +3.7 / −5.4，9 天也没有一天更差。
- **每个月方向一致**：4~9 月逐月都是 −32%~−35%，5 分钟保留率 +2.8~+3.4、假提醒率 −3.2~−4.0 个百分点（第八节）。
  四月单月 ≥5% 覆盖降 1.3 个百分点，超过判据的 1 个百分点（第一轮推荐同样超过），其余月份都满足。
- **提醒之后的方向仍不可预测**：15 分钟内「先顺势 1%」与「先逆势 1%」在两组参数下都约 47% 对 50%，与「方向几乎不可预测」的既有结论一致。
  新参数让提醒更干净、更少重复，不让提醒更能预测后续涨跌。
- **代价**：≥3% 大行情少报约 1.3 个百分点，首报晚约 14 秒；现行行情段约 6% 不再报（基本是只报 1 条的小波动）。
- **副作用：连续提醒几乎消失**（半年 5.7 → 0.5 条/天），需要用户决定是否把 `streak.min_alerts` 从 3 改为 2（改后约 4.9 条/天，质量未研究）。
- 与第一轮推荐相比：逐月都再少约 2~3 个百分点的提醒，重复率再低约 2.5 个百分点，5 分钟保留、假提醒略好，大行情覆盖只差 0.1~0.2 个百分点；
  而且冷却不变，少改一项。

在实时监控里，10-03~10-11 实时日志每天约 480~850 条秒级提醒（服务夜间常不在线），按 −37% 估计约为 300~540 条。

## 一、数据与方法（第一轮）

- **九月**：Gate 历史数据下载站的 2026-09 逐笔成交（`download.py`），合约是九月里曾进入秒级合约池的 114 个。
  合约池按 1 分钟 K 线估算滚动 24 小时成交额重建（`pool.py`，> 800 万进、≤ 640 万出，每 10 分钟刷新，与实时服务一致），
  平均同时在池约 33 个；只统计提醒时刻在池里的提醒。
- **十月**：Gate REST 逐笔成交（`fetch_oct.py`，只保留最近约 3~4 周），取 10-02 12:00 ~ 10-12 00:00（UTC），合约是实时日志里
  10-03~10-11 有过秒级提醒的 47 个；合约池用成交本身算 24 小时成交额（`oct_pool.py`）。更严的参数只会在现行参数提醒的附近触发，
  其余合约在新参数下同样不会提醒，所以只取这 47 个不影响新旧比较，但大行情只统计了这 47 个合约。
- **重放**：`record.py` 用 `src/price_alert/detectors/move/detector.py` 的检测器逐笔重放，记录每个窗口每一秒通过「宽松基准门槛」
  （短窗口 0.8% / 1.0 ATR、长窗口 1.0% / 1.2 ATR、笔数 1、确认 1、冷却 0）的判定指标；`sim.py` 在这份记录上按任意更严的参数离线重算
  确认、补齐秒、空档复核与冷却。`verify.py` 用真实检测器直接按参数重放对拍：RLC、BTW、BULLA 三个合约 × 三组参数（含一组每月 8 万条的宽松参数）
  **逐条完全一致**。
- **与实时日志对照**：用 9-26~9-28 当时的参数重放，实时服务在线的小时里两者几乎逐条一致（QNT 实时 36 条中 35 条、Q 实时 75 条中 73 条
  在重放里同一秒出现），差距来自实时服务夜间不在线和当时合约池门槛 1000 万，说明重放可信。

## 二、预先写定的口径与判据（看结果前写定，之后不改）

- 开发期 9-01~9-20 选参；九月留出期 9-21~9-30 和十月 10-03~10-11 只做验证。
- **单条质量**：15 分钟内价格先再顺势 1% 为「好」、先回到基准价（窗口起点价）为「假」；另看 5 分钟后是否仍保留至少一半位移。
  对称口径「先顺势 1% 还是先逆势 1%」随机游走下为 50%，只报告：「好」与「保留」天然偏向位移大的提醒，不能单独当作改进证据。
- **重复率**：同一合约同方向（任一窗口）5 分钟内已有提醒的条数占比。
- **行情段保留率**：现行参数的提醒按同合约间隔 >10 分钟分段，新参数仍至少报一条的段数占比。
- **大行情**：5 分钟收盘价变动 ≥3%（及 ≥5%）的连续区段（重叠的 5 分钟窗口合并），段内（起点到终点后 1 分钟）有同方向提醒算报到；
  首报延迟从区段起点算。九月开发期 ≥3% 3666 段、≥5% 1364 段；九月留出期 1374 / 434 段；十月 1003 / 318 段。
- **判据**（开发期，相对现行）：≥3% 覆盖率下降 ≤ 2 个百分点、≥5% 下降 ≤ 1 个百分点；两档首报中位延迟各增加 ≤ 20 秒；
  行情段保留率 ≥ 90%；5 分钟保留率不降、假提醒率不升。满足的组合里取每天提醒最少的；再看相邻参数（任一项挪一格）与两个留出期。
- **候选族**（`grid.py`，两窗口判定与冷却互不影响，分别重算再组合，共 49,344 组）：

| | 涨跌幅 % | ATR 倍数 | 窗口笔数 | 确认秒数 | 冷却秒数 |
|---|---|---|---|---|---|
| 短窗口（30 秒） | 1.2, 1.5, 1.8, 2.0 | 1.5, 2.0, 2.5 | 15, 30 | 2, 3 | 30, 60, 120, 300 |
| 长窗口（180 秒） | 1.6, 2.0, 2.5, 3.0 | 1.8, 2.2, 2.6, 3.0 | 30, 60 | 3, 5 | 180, 300, 600, 900 |

外加关闭长窗口。现行 YAML（短 1.2% / 1.5 ATR / 15 笔 / 确认 2 / 冷却 30，长 1.6% / 1.8 ATR / 30 笔 / 确认 3 / 冷却 180）在族内。

## 五、副作用：连续提醒

连续提醒由短窗口提醒串成（同合约同方向、间隔 ≤ 短窗口冷却 + 30 秒、第 3 条时报）。推荐参数下短窗口提醒少了约 3/4，
相邻同向提醒也更难在 90 秒内连上（`streak_count.py`，没有模拟「累计方向不一致时先不报」，只看数量级）：

| | 九月 | 十月 |
|---|---|---|
| 现行 | 7.0 条/天 | 4.3 条/天 |
| 推荐 | 0.5 条/天 | 0.3 条/天 |
| 推荐 + `streak.min_alerts: 2` | 4.4 条/天 | 2.7 条/天 |

`min_alerts` 改为 2 能让数量回到现行水平，但这组连续提醒的质量没有研究过，留给用户决定。

## 六、研究过、没有采用的

- **冷却按方向分别计算**（`dircd.py`，要改检测器，不是参数）：现行冷却不分方向，急跌提醒后几分钟内的反向急拉会被冷却挡掉，
  这是加长长窗口冷却会丢大行情的主要原因。在推荐参数上把长窗口冷却改为 300 秒：不分方向时每天 595 条（−42%）、≥3% 覆盖 83.6%；
  按方向时 651 条（−37%）、≥3% 覆盖 87.2%（高于推荐参数的 86.7%），重复率 29% → 20%。比推荐参数再少约 4 个百分点，收益不大，
  需要时可以单独做。

- 开发期在前两轮已用过；质量分在约束下的差距（0.2~0.4 个百分点）只比自助法区间略宽，第三轮相对第二轮的改进主要体现为少报约 6%、
  重复率再低约 4.6 个百分点，质量本身已到平台。
- 确认 5 秒意味着短窗口提醒至少比满足门槛的第一秒晚 4 秒；短窗口每天只剩约 38 条，基本退化为「30 秒内 ≥3% 的急拉急跌」专用。
- 其余同第八节（幸存者偏差、合约池估算）。
