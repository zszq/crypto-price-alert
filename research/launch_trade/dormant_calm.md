# 冷门启动：涨前平稳、涨幅是涨前波动的很多倍（2026-10-22）

用户看了最近一天的冷门启动提醒后指出：ORBIO 涨之前价格就来回乱跳，IRYS（2026-10-21 北京 14:17 之前）几乎是一条直线；
要的是「涨之前近乎一条直线、波动很小，涨起来之后的涨幅是涨前平均波动的很多倍」，而且涨的过程中不能有很大的单分钟跳涨。
脚本：`dormant_calm.py`。冷门、冷门启动行情、「准」的口径与 `dormant_solo.md` 第一节完全相同（直接沿用其代码），
只换检测器的候选族。

## 一、预先写定的口径与判据（跑数之前写下，之后不改）

### 1. 新增的三个量（都只用窗口开始之前或窗口之内已收盘的 K 线）

- **涨前波动 V**：窗口开始之前 N 分钟，每分钟真实波幅的平均值（%）。真实波幅 = (max(最高, 前收) − min(最低, 前收)) ÷ 前收，
  没有成交的平线分钟为 0，所以「一条直线」的 V 接近 0。N ∈ {60, 240}。
- **倍数 K**：窗口涨幅（%，窗口前一根收盘 → 最后一根收盘）÷ V。V = 0 时 K 视为无穷大。
- **最大单分钟涨幅 J**：窗口内每根 K 线收盘相对前一根收盘的涨幅的最大值（%）。

### 2. 检测器与候选族

每分钟收盘后对最近 W 根 1 分钟 K 线判定，全部满足才提醒：之前 24 小时成交额 ≤ 100 万；窗口成交额 ≥ Q；窗口涨幅 ≥ C；
窗口内有成交的分钟数 ≥ A；**V ≤ F；K ≥ Kmin；J ≤ Jmax**；同一合约距上次提醒不足 60 分钟不报。
后三项是用户这次的要求，候选族里每一组都必须带倍数与单分钟涨幅两项（F 可以不限）。

| 参数 | 候选值 |
|---|---|
| 窗口 W（分钟） | 10, 15, 20, 30 |
| 窗口成交额 Q（USDT） | 5 千, 1 万, 2 万, 5 万 |
| 涨幅下限 C（%） | 5, 8, 12 |
| 活跃分钟数 A | ≥ 1, ≥ ⌈W/2⌉, = W |
| 涨前波动的统计长度 N（分钟） | 60, 240 |
| 涨前波动上限 F（%/分钟） | 不限, 0.5, 0.2 |
| 倍数下限 Kmin | 5, 10, 20, 50 |
| 最大单分钟涨幅上限 Jmax（%） | 3, 5, 8 |

共 4 × 4 × 3 × 3 × 2 × 3 × 4 × 3 = 10,368 组。

**基准**：现行冷门启动默认参数（`dormant_solo` 的选中方案：W 10、Q 2 万、C 8%、A ≥ 5、冷却 60，不带后三项），
在本脚本里用同一套数据与代码重新计算开发期、样本外的准确率（应与 `dormant_solo.md` 的 0.399 / 0.426 一致，作为对拍）。

### 3. 选参与判据（全部满足才替换现行默认参数；没达标直接剔除、不降级、不改用第二名）

1. **只用开发期选参**：开发期准确率不低于基准开发期准确率的候选里，开发期 F0.5 最高的一组，只此一组；没有就是没有方案。
2. **PBO < 0.5**：开发期按时间切 16 段做 CSCV，每种切分在 IS 内同样先按准确率 ≥ 基准开发期准确率过滤再取 F0.5 最高者。
3. **样本外比现行更准**：样本外准确率高于基准样本外准确率，按周循环块自助法（块长 4 周、2000 次）单侧 p < 0.05；
   4 种设置（(3%,60)、(3%,240)、(5%,60)、(5%,240)）的准确率各自不低于基准。
4. **可行**：样本外每天提醒 1 ~ 50 条（全市场合计）。

召回率不作判据（用户要的是更窄的形态，召回必然下降），只报告。
另报告但不作判据：是否达到现行放量上涨的准确率（样本外 0.437）；IRYS 2026-10-21 北京 14:17 之后的那段拉升会不会报、
最近一天 ORBIO 的提醒还在不在。

不测试任何按一天中时段过滤的方案。

## 二、结果

数据到 2026-10-22，开发期 174 周，样本外 95 周。`verify` 用逐分钟直接实现在候选最多的冷门币上对拍 4 组参数（含基准），
80 条提醒全部一致。基准在本脚本里重算：开发期准确率 0.399、样本外 0.426，与 `dormant_solo.md` 一致。

### 1. 开发期选出的方案

10,368 组里开发期准确率 ≥ 0.399（基准）的有 3,766 组，其中 F0.5 最高的一组：

| 参数 | 取值 |
|---|---|
| 窗口 / 成交额 / 涨幅 / 活跃分钟 | 10 分钟 / ≥ 5 千 / ≥ 8% / ≥ 5 |
| 涨前波动 | 按之前 240 分钟算，不设上限 |
| 倍数 / 最大单分钟涨幅 | ≥ 10 倍 / ≤ 5% |

开发期准确率 0.399（与基准持平）、F0.5 0.168（基准 0.174），PBO 0.00。涨前波动上限（「一条直线」）一项都没被选上。
族里开发期准确率最高的一组 0.484（W10、成交额 ≥ 5 万、涨幅 ≥ 12%、倍数 ≥ 50），每天 0.27 条、召回率 0.2%。

### 2. 逐项判据

| 判据 | 结果 |
|---|---|
| ① 开发期准确率 ≥ 基准中 F0.5 最高 | 有（上表） |
| ② PBO | 0.00 ✓ |
| ③ 样本外准确率高于基准 0.426，自助法 p < 0.05 | 0.436，p = 0.11 ✗ |

| ④ 每天 1 ~ 50 条 | 8.8 条 ✓（基准 10.9 条；召回率 6.8%，基准 8.6%） |
| **结论** | **不通过：样本外比现行略准，但差距在统计上站不住，不替换现行默认参数** |

### 3. 解读

- 「倍数 + 单分钟涨幅上限」让样本外准确率从 0.426 到 0.436（约等于现行放量上涨的 0.437），提醒少两成，但这点提升
  在 95 周里有 11% 的概率只是运气。
- 「涨前近乎一条直线」本身并不让提醒更准，反而更差。按用户字面描述另算的几组（不是选出来的，只供解读，涨前波动按 240 分钟、
  上限 0.2%/分钟、单分钟涨幅 ≤ 5%）：W20 倍数 ≥ 20 样本外 0.347、W10 倍数 ≥ 20 0.367、W30 倍数 ≥ 50 0.404，
  都低于现行的 0.426。冷门币横盘越久、盘口越薄，第一波拉起来之后越容易先回落 3%。
- IRYS 2026-10-21：字面形态的几组都在北京 14:55 报出（价 0.01456），但两分钟后就跌破 −3%（15:02 最低 0.01366，−6%）才再涨上去，
  按「先涨 3%」算不准；选中方案在这一天不报 IRYS。ORBIO 在最近一天的 3 条（基准）选中方案报其中 1 条（17:07），
  另在 13:25 多报一条。

结果文件：`data/backtest/results/dormant_calm/select.json`、`evaluate.json`。

## 四、用户指定：总实体占比 ≥ 60%（2026-10-23）

用户看了 10-22 的提醒后要求：拉升的 K 线上影线过多（窗口总实体占比 < 60%）不提醒。总实体占比 = 窗口各根 K 线 |收 − 开| 之和
÷ (最高 − 最低) 之和，与趋势提醒同一口径；60% 是用户给定的值，**没有在开发期选参，也没有跑第一节的判据**，只报告它对现行方案和
字面形态的影响（同一套候选与「准」的口径，加这一条后冷却照常从下一次满足条件的分钟算）。脚本在会话草稿里，没有入库。

| 方案 | 实体占比下限 | 开发期准确率（条/天） | 样本外准确率（条/天） | 样本外 4 种设置 |
|---|---|---|---|---|
| 现行（第二节选中方案） | 不限 | 0.399（3.9） | 0.436（8.8） | 0.446 / 0.455 / 0.402 / 0.440 |
| | 50% | 0.398（3.5） | 0.434（7.7） | 0.446 / 0.455 / 0.399 / 0.438 |
| | **60%** | **0.398（2.8）** | **0.434（5.9）** | 0.443 / 0.454 / 0.399 / 0.437 |
| | 70% | 0.397（1.9） | 0.429（3.2） | 0.439 / 0.452 / 0.394 / 0.430 |
| 字面 W20（倍数 ≥ 20） | 不限 / 60% | 0.318 / 0.319 | 0.347（20.3）/ 0.345（16.2） | |
| 字面 W10（倍数 ≥ 20） | 不限 / 60% | 0.339 / 0.340 | 0.367（14.2）/ 0.365（11.2） | |

结论：实体占比过滤对准确率基本没有影响（± 0.01 以内，门槛越高略降），只是少报：60% 让现行方案的提醒少三分之一。
注意每分钟只有一两笔成交、靠跳空往上走的拉升 K 线开收相同、没有实体，也会被这一条挡掉。按用户要求采用 60% 作为
`min_body_ratio` 的默认值，这是例外，不代表通过了判据。

## 五、冷却期内的「第 N 波」补报（2026-10-23）

用户反馈冷却 60 分钟太长，第一次提醒没注意就整段错过。以下判据在跑数前写定（脚本在会话草稿 `dormant_wave.py`，没有入库）。

**口径**：基础规则为第四节加实体占比后的现行规则。满足条件时，距上次提醒（含补报）≥ 60 分钟照常报（第 1 波）；
不足 60 分钟时，距上次 ≥ G 分钟且收盘价 ≥ 上次提醒价 × (1 + S%) 才再报（波次 + 1）；每次提醒都更新上次提醒的时间与价格。
候选族 S ∈ {3, 5, 8, 10}、G ∈ {1, 10}，共 8 组；基准为冷却内不再报。

**判据**：① 开发期波次提醒准确率 ≥ 基准开发期准确率的组里，取开发期波次条数最多的一组；② PBO < 0.5；
③ 样本外波次提醒准确率 ≥ 基准样本外准确率、4 种设置各自不低于基准、整体准确率不低于基准 0.01 以上；④ 样本外波次提醒每天 ≥ 0.5 条。

**结果**：选中 S 3%、G 1（每分钟都可补报，即不另设间隔）。

| 判据 | 结果 |
|---|---|
| ① 开发期波次准确率（基准 0.398） | 0.416，909 条 ✓ |
| ② PBO | 0.18 ✓ |
| ③ 样本外波次准确率（基准 0.434） | 0.478 ✓（自助法下低于基准的概率 0.00） |
| ③ 4 种设置 | 0.486 / 0.486 / 0.466 / 0.476 vs 0.443 / 0.454 / 0.399 / 0.437 ✓ |
| ③ 整体 | 0.444 ✓ |
| ④ 每天波次提醒 | 1.61 条 ✓（整体从 5.9 到 7.4 条） |

样本外按波次：第 1 波 0.434（3882 条）、第 2 波 0.468（813）、第 3 波 0.511（183）、第 4 波及以后 0.510（73）。
79% 的拉升只报 1 次，16% 报 2 次，最多 7 次。第 2 波中位在第一次提醒后 4 分钟、价格高约 5%。
G 10 的各组都更差（0.455 ~ 0.502，显著性不足）。波次提醒与同一段的第一次提醒高度相关，不是独立的机会。

**通过判据**，按用户要求加入 `dormant/`（`realert_step_percent` 默认 3）。
